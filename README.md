## 二、遵循成果包的关键约定

### 2.1 数据模型（图 4-8 ERD，SQLite 落地）
完整落地 21 张核心表：`t_user / t_user_profile / t_user_behavior / t_category / t_category_attr /
t_index_mapping / t_product / t_sku / t_sku_attr_value / t_inventory / t_cart_item / t_order /
t_order_item / t_payment / t_conversation / t_message / t_knowledge_chunk / t_bundle /
t_bundle_item / t_recommend_log / t_session`。字段名、主外键、状态枚举与 ERD 一一对应。

### 2.2 接口约定（图 4-2 / 4-10）
- 分层对应：`controller`（REST 路由）/ `application`（应用服务）/ `domain`（品类引擎领域服务）/
  `ai`（能力中台）/ `repository`（SQLite 仓储）。
- 下单支付时序（`createOrder → lockStock → 支付网关统一下单 → 异步回调验签+幂等 → deductStock → 已支付 → 发布 OrderPaid 触发履约`）已逐段实现。
- 订单状态机（图 4-7）：`待支付(10)→已支付(20)→待发货(30)→已发货(40)→已完成(50)`，含 `已关闭(60)/退款中(70)/售后中(80)/已退款(90)`，守卫条件（取消/超时/发货/确认收货）均已落地。
- AI 降级契约：所有 AI 接口响应均返回 `degraded` 与 `degradeReason` 字段，AI 异常不阻断交易主流程。

### 2.3 品类引擎（图 3-6 / 4-9）
`importCategory` 五步处理：JSON 语法解析（含行号定位）→ Schema 校验（编码唯一性 / 层级深度≤5 / 类型白名单 / 枚举 valueRange）→ 品类树构建 → 检索与筛选索引映射生成 → 事务落库；并据属性 Schema **自动生成动态商品发布表单**（无需为新增品类开发页面）。

## 三、技术选型

| 层 | 选型 | 说明 |
|---|---|---|
| 前端 | 原生 HTML + CSS + JavaScript（SPA，hash 路由） | 零构建依赖、可离线；沿用成果包品牌视觉（科技蓝 `#1F4E79` / 微软雅黑 / 卡片式） |
| 后端 | Python 3.13 + Flask | 轻量 REST 服务，路由即控制器层 |
| 数据存储 | SQLite 3（文件库 `backend/ai_ecp.db`） | 零外部依赖、随站运行；生产可平滑替换为 MySQL（ER 表结构已对齐） |
| AI 能力 | 规则+模板模拟 `ILlmGateway` / `IVectorRetriever` | 接口契约与降级机制完整，可直接替换为生产大模型/向量库 |
| 运行环境 | 受管 Python venv（`python -m venv`） | 依赖隔离，仅 Flask 一个第三方包 |

> 选择 SQLite + 原生前端 + Flask 的组合，关键在于**零外部服务、一条命令即可运行**，同时满足"动态数据交互 + 业务闭环"目标；ER 模型与接口约定与成果包完全一致，技术栈可平滑升级（MySQL/Redis/真实大模型）。

## 五、数据存储方案（SQLite 表 → 业务对象映射）

- **用户与商家**：`t_user`(含 role) + `t_user_profile`(画像) + `t_user_behavior`(行为埋点，供选品召回)
- **品类体系(JSON 自定义)**：`t_category`(父子层级、path、version、is_leaf) + `t_category_attr`(属性 Schema) + `t_index_mapping`(检索/筛选索引)
- **商品与库存**：`t_product` → `t_sku`(多规格) → `t_sku_attr_value`(属性值) → `t_inventory`(总量/锁定量，乐观锁 version)
- **购物车**：`t_cart_item`(按用户，含 source 标记 manual/recommend/bundle)
- **交易**：`t_order`(状态机) → `t_order_item` → `t_payment`(渠道/状态/交易号)；下单时**行级锁库存**(locked_qty+)，支付回调**扣减**(total_qty−, locked_qty−)
- **AI 能力**：`t_conversation`/`t_message`/`t_knowledge_chunk`(客服知识库) + `t_bundle`/`t_bundle_item`(组货) + `t_recommend_log`(选品/履约日志)

## 八、业务流程闭环验证（已通过）

1. 登录 → 浏览/搜索商品 → 加入购物车 → 结算唤起收银台
2. 创建订单（**锁定库存**，状态=待支付）→ 模拟支付网关统一下单 → 支付回调（验签+幂等）→ **扣减库存** → 状态=已支付 → 触发履约
3. 商家后台发货（录入运单号）→ 状态=已发货 → 消费者确认收货 → 状态=已完成
4. 库存不足时下单被拒（409），保障数据一致性
5. 品类 JSON 导入：合法则落库并生成动态表单；编码重复则 422 返回逐条校验错误
6. AI 能力均返回 `degraded` 标记，演示降级契约生效

> 结论：网站已具备**动态数据交互**（前后端 REST 实时读写 SQLite）与**基本业务流程闭环**（注册登录→浏览搜索→购物车→下单支付→订单/库存状态联动→后台履约）。

## 九、新增功能说明（本次迭代）

### 9.1 商品图片展示与列表/详情视图增强

**核心能力**
- 演示商品由 4 件扩充至 **15 件**，覆盖 4 个品类（手机 / 手机配件 / 智能穿戴 / 图书），每件含多 SKU 与库存。
- 新增动态商品图路由 `GET /img/product/<pid>`：按品类自动配色、配图标（📱手机 / 🎧配件 / ⌚穿戴 / 📚图书），以 SVG 实时生成商品图（`product_images.py`）。**零外部图片依赖**，商家后台新发布商品同样自动获得图片。
- 商品卡片（首页精选 / 列表页）、商品详情（主图 + 缩略图集）、购物车行、后台商品表格均展示图片；图片缺失时自动回退为品类文字占位。
- 商品列表页新增 **网格视图（▦）/ 列表视图（☰）切换**：网格适合图片浏览，列表信息密度更高（分类+库存+价格一行呈现）。

**适用场景**：买家浏览比价、商家巡检自家商品图、演示/教学环境无真实素材时快速获得"有图"的浏览体验。

**预期输出**：列表/详情/购物车/后台均可见带图商品；`/img/product/1` 返回 `image/svg+xml`（带 24h 缓存头）；视图切换即时生效且记住选择。

### 9.2 商家后台入口、访问权限与店铺基本信息

**核心能力**
- **入口**：商家/管理员登录后，顶栏出现「商家后台」入口（首页 CTA 亦有「进入商家后台」）；消费者不可见。
- **访问权限（双层防护）**：
  - 前端路由拦截：消费者访问 `#/admin` 显示「无访问权限」面板并引导去逛商品；
  - 后端接口拦截：全部 `/api/admin/*` 经 `@login_required(roles=("merchant","admin"))` 校验，消费者访问返回 **403**。
- **后台五个管理模块**（顶栏 Tab 切换，看板页内置"能力·场景·交互"说明面板）：
  | 模块 | 核心能力 | 适用场景 | 交互方式 |
  |---|---|---|---|
  | 经营看板 | 本店商品数/订单数/已支付金额/待发货/状态分布（商家维度过滤） | 每日经营巡检 | 进入后台默认页 |
  | 商品管理 | 发布多 SKU 商品（含动态属性表单）、查看 SKU 库存 | 上新、补货、调价 | 表格 + 弹窗表单 |
  | 订单管理 | 录入运单号发货、异常订单退款 | 履约与售后 | 表格内「发货/退款」按钮 |
  | 基本信息 | 维护店铺名称、简介、联系电话、地址 | 店铺装修与客服联系 | 表单保存（`GET/PUT /api/admin/profile`） |
  | 品类(JSON) | JSON 自定义品类树与属性 Schema，自动生成动态发布表单 | 扩展经营类目 | 粘贴 JSON → 导入 → 预览表单 |
- 看板统计已按**商家维度过滤**（仅统计本店商品/订单），管理员视角为全平台。

**适用场景**：多角色权限隔离演示、商家自助开店装修、平台治理。

**预期输出**：商家登录→顶栏出现后台入口→五 Tab 完整可用；消费者访问后台被前端拦截且接口 403；店铺信息保存后回显并同步更新顶栏昵称。
